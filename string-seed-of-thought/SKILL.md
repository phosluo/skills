# String Seed of Thought（SSoT）

先生成复杂字符串，再通过分段、字符运算或模式联想，让字符串实际参与任务中的选择。跨领域复用这一过程，而不是将所有答案随机化。

## 1. 找到可以变化的部分

确认用户要完成的任务、交付形式、答案数量及必须保持的约束。把事实、正确性条件、接口契约、用户偏好与可变化的视角、结构、策略或样例区分开。目标不明时询问目标；不必为了应用 SSoT 额外问一轮偏好。

按实际需要选择路径：

- **多样性生成（DAG）**：任务有多个有效答案，希望跳出惯常答案，或探索不同方案。
- **概率选择（PIF）**：用户明确要求在给定选项间等概率或按指定概率抽样。
- **混合任务**：先按指定概率选类别，再在该类别内生成内容。分别处理概率约束与内容质量。

对于只有一个正确答案的任务，正常求解。若用户明确要求用 SSoT，可将它用于探索不同证明路线、排错假设或解释方式，再独立验证；不要随机选择事实、计算结果或最终诊断。

## 2. 生成种子

本 skill 默认采用工具辅助变体：通过 shell 执行下列脚本，用外部随机源生成种子，再读取实际工具输出参与后续选择。相对路径以本 skill 所在目录为基准：

```bash
bash scripts/generate-seed.sh
```

脚本使用 OpenSSL 生成 256 个字母数字字符；该长度是本 skill 的实践选择，不是论文规定。不要让 AI 自行编造或补全字符串。用户明确给定种子时直接使用，无需重新生成。

若 OpenSSL 不可用，可通过 shell 调用其他系统随机源生成等价字符串。若 shell 无法执行或随机源不可用，说明限制并请求用户提供种子，不回退到模型自行生成，也不声称已完成随机生成。

每个新的独立答案使用新种子；同一方案的润色沿用既有选择。不要先决定答案再编造种子佐证，也不要为了抽中喜欢的结果反复换种子。

无需展示种子或完整中间推导。默认将字符串留在工作过程，不嵌入交付内容；用户明确要求种子或复现信息时，可给出种子、映射规则和简短选择记录。相同字符串本身不保证模型输出逐字一致。

## 3A. 多样性生成

找出少量真正影响答案的变化维度。根据任务临时构建可行选项，不使用所有领域共用的固定风格表。例如：

| 任务 | 可变化的维度 | 保持不变的要求 |
| --- | --- | --- |
| 写作、命名、传播 | 叙述者、冲突、结构、语气、意象 | 受众、真实信息、篇幅 |
| 产品、商业、规划 | 目标切口、交付机制、渠道、实施顺序 | 预算、资源、用户目标 |
| 分析、研究 | 假设、比较基准、观察尺度、反例方向 | 证据标准、事实与假设的区分 |
| 编程、排错 | 算法路线、分解方式、故障假设 | 功能语义、接口、测试要求 |
| 测试、教学、模拟 | 边界情境、案例背景、解释方式 | 正确答案、覆盖目标、领域约束 |
| 视觉设计 | 构图、色彩关系、排版、视觉语言 | 内容、品牌要求、可读性 |

操纵不同字符串片段，选择或组合这些维度。可用字符码求和取模、滚动哈希或局部模式联想；选择对当前任务有用的方式即可。不要只展示字符串却继续输出完全不受其影响的惯常答案。

将选中的元素整合成一个连贯、可用的结果。对不相容组合做最小调整，保留有意义的差异。按用户要求完成实际工作，不停留在“可以从这些方向思考”。未指定数量时默认给一个完整答案；不要擅自膨胀成大量候选。

用户要求多个方案时，检查它们是否在机制、结构、假设或体验上有实质差别。仅更换措辞或名称不算多样性。如果最终要推荐一个，用明确的任务标准评估候选，而非随机指定赢家。

## 3B. 概率选择

先固定选项、顺序和目标概率，再操纵字符串作选择。用户给的是权重时按总权重归一化；明确给的是概率且总和明显不为 1 时询问或指出问题，不擅自修改。不要把“帮我选最好的”理解成随机抽样。

原始方法可采用字符码求和取模，或滚动哈希后划分阈值区间。例如，等概率二选一可用字符码总和的奇偶性；非等概率选择可将哈希值映射到区间，再按累计概率选择。这些是操作示例；外部随机种子并不自动保证后续映射无偏或手算结果正确。

若任务要求可靠的概率实现或可复现模拟，使用可验证的程序随机采样与固定映射，说明采用工具辅助方式；不要把未经验证的心算取模说成精确抽样。实现时避免直接对不适配的有限随机整数取模造成偏差，可用成熟采样库或拒绝采样。复现时保存种子、算法、选项顺序及必要的版本信息。

在概率任务中，不要因结果不喜欢而重抽、去重或强行平衡短序列；这些操作会改变分布。若用户要求的是固定比例配额、无放回抽样或均衡测试覆盖，按该要求实现，而不是默认独立抽样。一次结果不能验证概率分布；仅在用户要求评估时用多次试验检查频率和误差。

## 4. 验证并交付

按原任务验收：创作检查连贯性与适配度，研究检查证据，代码检查行为，样例检查合法性，概率任务检查映射与抽样设置。新颖性不能替代正确性；用标准修正结果时不必重新抽取种子。

回复以用户需要的产物为主，必要时简述使用的方向或选择规则。将假设、虚构情境和事实区分清楚。不要保证“每次必然独一无二”“所有任务都会更好”或“输出严格服从目标分布”。

## 方法来源与证据范围

- [Sakana AI：String Seed of Thought](https://pub.sakana.ai/ssot/)
- [论文：String Seed of Thought: Prompting LLMs for Distribution-Faithful and Diverse Generation](https://arxiv.org/abs/2510.21150)

原方法的核心是模型先生成字符串，再操纵字符串引导随机决策，无需训练或外部工具。本 skill 按用户偏好改用 shell 和外部随机源生成字符串，属于工具辅助变体。原文报告了五个前沿模型的 PIF 实验，以及 DeepSeek-R1 在 NoveltyBench 上的 DAG 多样性收益；效果取决于模型和任务。此处对研究、编程、规划等领域的用法是该过程的应用扩展，不代表论文逐项验证了这些场景或本变体。
